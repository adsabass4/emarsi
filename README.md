# مُراقب تقاطع EMA على OKX (Emarsi)

أداة **مراقبة وتنبيه فقط** — بدون أي منطق تنفيذ أوامر شراء/بيع تلقائي. القرار النهائي يبقى يدويًا دائمًا.

<div dir="rtl">

| | |
|---|---|
| **الوظيفة** | يمسح كل أزواج التداول النشطة (USDT Spot) على منصة OKX بشكل دوري |
| **الإشارة** | تقاطع صاعد `EMA9` فوق `EMA21` + `RSI14` بين 45–65 + حجم أعلى من متوسط آخر 20 شمعة — تُحسب على **فريمين** (1H و4H) بشكل مستقل |
| **التنبيه** | رسالة تيليجرام لكل (عملة + فريم) جديد يطابق الشرط (مع منع تكرار الإشعارات) |
| **الواجهة** | لوحة تحكم ويب واحدة (عربي RTL) تتحدث تلقائيًا كل دقيقة، مع تبديل فوري بين 1H / 4H |
| **البيانات** | OKX **Public Market Data API** فقط — لا حاجة لمفتاح أو حساب OKX |
| **التشغيل** | `docker compose up` (يعمل على x64 وأيضًا ARM64: Oracle Cloud Free Tier / Raspberry Pi) |

## 1) ما الذي يفعله بالضبط؟

1. يستدعي `GET /public/instruments?instType=SPOT` ويصفي `state == "live"` و `quoteCcy == "USDT"` → قائمة بكل الأزواج النشطة (ليست قائمة يدوية).
2. يطبّق **فلتر السيولة** (طلب `GET /market/tickers?instType=SPOT` واحد): الأزواج التي حجمها اليومي `volCcy24h` أقل من `MIN_VOLUME_USD_24H` تُستبعد نهائيًا قبل أي طلب شموع.
3. لكل عملة ولـ**كل فريم مفعّل** (`TIMEFRAMES`، افتراضي `1H,4H`) يجلب الشموع `GET /market/candles?bar=<الفريم>&limit=120` **+ سلسلة قصيرة واحدة** `bar=5m` (لحساب نوافذ "نسبة التغير") مع احترام حد الطلبات عبر طابور:
   - `6` طلبات متزامنة كحد أقصى (`CONCURRENCY`).
   - نافذة زمنية تمنع أكثر من `16` طلبًا لكل ثانيتين (`REQUESTS_PER_2S`) — حد OKX العام ~20 طلب/2ث، مع هامش أمان. كل طلبات الفريمين تمر عبر نفس الطابور، فلا يتجاوز الحد حتى لو ضُعفت الشموع.
   - إعادة محاولة واحدة لكل فشل عابر (شبكة / 429) مع انتظار قصير.
4. يحسب من **الشمعة المقفلة** (حقل `confirm`) فقط، **على كل فريم بحده**:
   - `EMA 9` و `EMA 21` (بذر SMA كالمعتاد).
   - `RSI 14` بطريقة Wilder.
   - متوسط حجم آخر 20 شمعة.
5. العملة (على فريم معين) **مطابقة** فقط إذا تحققت الثلاثة معًا:
   - `EMA9` يعبر من تحت `EMA21` إلى فوقه في آخر شمعة مقفلة **و** `45 ≤ RSI ≤ 65` **و** `حجم آخر شمعة > متوسط 20 شمعة`.
   - يمكن أن تطابق على 1H فقط، أو 4H فقط، أو عليهما معًا.
6. يخزّن كل دورة في SQLite بصف لكل **(`symbol`, `timeframe`)**، ويرسل تنبيه تيليجرام لكل (عملة + فريم) **جديد** فقط — لو طابقت على الفريمين معًا تُرسل رسالتان منفصلتان.
7. يكرر الدورة كل `15` دقيقة (`node-cron`، دورة فورية أولى عند الإقلاع).

> **مهم:** لا يُرسل تنبيه مكرر لـ (عملة + فريم) طالما ما زالت مطابقة. ما إن تتوقف عن المطابقة على فريم يُتاح إرسال إشعار جديد إذا عادت إشارتها لاحقًا — لكل فريم على حدة.

## 2) المتطلبات

- **على جهازك:** `Docker` + `Docker Compose` (الأسهل).
- **أو مباشرة:** Node.js **22.5+** (نستخدم وحدة `node:sqlite` المدمجة، فلا حاجة لأدوات C++).

## 3) التشغيل محليًا (الأسلم: Docker)

```bash
git clone <هذا المستودع> && cd emarsi
cp .env.example .env          # ثم عدّل ملف .env
docker compose up -d --build
```

- لوحة التحكم: `http://localhost:3000`
- السجلات: `docker compose logs -f scanner`
- إيقاف: `docker compose down` (البيانات محفوظة في volumes مجردة تبقى).

### 3.1) بدون Docker (Node مباشرة)

```bash
npm install
cp .env.example .env
# عدّل .env (ضع التوكن على الأقل)
npm start
```

أوامر مفيدة:

```bash
npm run scan-once            # تنفيذ دورة واحدة فقط ثم خروج (اختبار)
DRY_RUN=true npm start       # يسجل "كان سيرسل تنبيه" بدون إرسال فعلي
npm test                     # تشغيل الاختبارات (33 اختبارًا)
```

## 4) إنشاء بوت تيليجرام والحصول على الـ Chat ID

1. افتح تيليجرام وابحث عن **@BotFather**.
2. أرسل `/newbot` ثم اختر اسمًا (مثل `OKX EMA Scanner`) ثم اسم مستخدم ينتهي بـ `bot` (مثل `okx_ema_scanner_bot`).
3. سيعطيك توكنًا مثل:
   ```
   123456789:AAEexample-token-xyz
   ```
   ضعه في `.env` داخل `TELEGRAM_BOT_TOKEN=...` واحفظه في مكان آمن.

4. احصل على `TELEGRAM_CHAT_ID`:
   - **لإرسالها لنفسك:** أرسل أي رسالة للبوت (اضغط Start)، ثم نفّذ:
     ```bash
     curl https://api.telegram.org/bot<TOKEN>/getUpdates
     ```
     وابحث في الجواب عن `"chat":{"id":123456789}`.
   - **لإرسالها لمجموعة:** أنشئ مجموعة، أضف البوت إليها **كمشرف**، أرسل رسالة فيها، ثم افحص `getUpdates`.
   - وسيلة بديلة سريعة: بوت **@RawDataBot** أو **@userinfobot** يُظهر لك Conversation ID مباشرة.

5. املأ القيم في `.env` وأعد تشغيل الخدمة. أول (عملة + فريم) مطابقة ستصل رسالتها بصيغة:
   ```
   🔔 BTC-USDT — تقاطع صاعد (4H) | RSI: 56.04 | السعر: 72000.5
   ```
   ولو طابقت نفس العملة على الفريمين معًا تصلك رسالتان منفصلتان (واحدة بـ `(1H)` والأخرى بـ `(4H)`).

## 5) ملف الإعدادات (`.env`)

كل القيم قابلة للتعديل بدون لمس الكود:

| المتغير | المعنى | الافتراضي |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | توكن بوت تيليجرام (من BotFather) | فارغ = تعطيل التنبيهات |
| `TELEGRAM_CHAT_ID` | رقم المحادثة/ المجموعة | فارغ |
| `SCAN_INTERVAL_MINUTES` | مدة دورة المسح بالدقائق | `15` |
| `SCAN_CRON` | تعبير cron يدوي (له الأولوية على المدة) | فارغ |
| `CYCLE_TIMEOUT_MINUTES` | حارس الجدولة: إذا استمرت دورة أطول من هذا، يحرّر القفل تلقائيًا وتبدأ الدورة الجاية (0 = تلقائي: الأكبر بين الفترة و25) | `0` |
| `STALE_FACTOR` | تضاعف الفترة الذي بعده تُعلَم البيانات "قديمة" في الـAPI واللوحة | `1.5` |
| `EMA_FAST` / `EMA_SLOW` | سرعة وحدود EMA | `9` / `21` |
| `RSI_PERIOD` | فترة RSI | `14` |
| `RSI_MIN` / `RSI_MAX` | نطاق RSI المقبول | `45` / `65` |
| `VOLUME_SMA` | عدد الشموع لمتوسط الحجم | `20` |
| `TIMEFRAMES` | الفريمات المفحوصة في كل دورة (مفصولة بفواصل؛ ضع فريمًا واحدًا لتعطيل الباقي) | `1H,4H` |
| `TIMEFRAME` | الفريم المبدئي المعروض في اللوحة (يجب أن يكون ضمن `TIMEFRAMES`) | `4H` |
| `CHANGE_BAR` | دقة سلسلة حساب "نسبة التغير" في اللوحة (نوافذ 5م/15م/1س/4س تُشتق منها) | `5m` |
| `CANDLES_LIMIT` | عدد الشموع لكل عملة | `120` |
| `OKX_BASE_URL` | رابط OKX العام (للمرايا/البروكسيات) | `https://www.okx.com/api/v5` |
| `CONCURRENCY` | أقصى طلبات متزامنة | `6` |
| `REQUESTS_PER_2S` | أقصى طلبات لكل ثانيتين (احترام Rate Limit) | `16` |
| `REQUEST_TIMEOUT_MS` | مهلة الطلب | `10000` |
| `RETENTION_DAYS` | مدة حفظ سجل الأدوار ثم الحذف | `30` |
| `TURSO_DATABASE_URL` | رابط قاعدة بيانات Turso السحابية (`libsql://...` أو `https://...`) | فارغ = ملف محلي `data/scanner.db` |
| `TURSO_AUTH_TOKEN` | توكن الوصول إلى Turso | فارغ (مطلوب عند ضبط الرابط) |
| `PORT` | منفذ لوحة التحكم | `3000` |
| `TZ` | المنطقة الزمنية | `UTC` |
| `DRY_RUN` | `true` يسجل التنبيهات دون إرسال (تجربة) | `false` |

> ملاحظة: `SCAN_INTERVAL_MINUTES` يعمل كـ interval (`*/N * * * *`). إذا أردت جدولة أدق استخدم `SCAN_CRON` مثل `*/10 * * * *`.

#### متانة الجدولة (لا تتجمد بعد أول دورة)
- **قفل واحد** يمنع تداخل الدورات، ويُحرَّر **دائمًا** حتى لو فشلت الدورة أو رمى تخزين الحالة خطأً — لا يبقى عالقًا للأبد.
- **حارس مدة الدورة** (`CYCLE_TIMEOUT_MINUTES`): إذا علقت دورة تتجاوز الحد، يُسجَّل `ERROR ... forcing release` وتُفرَّج القفل لتبدأ الدورة التالية من جديد بدل رسالة `skipping` المتكررة إلى الأبد.
- **شبكة أمان العملية**: أي `uncaughtException`/`unhandledRejection` يُسجَّل بالـstack ثم يخرج الرمز `1` فيعيد Docker (`restart: unless-stopped`) أو systemd/pm2 تشغيله — لا موت صامت.
- **إنذار قدم البيانات**: `/api/health` و`/api/overview` يرجِعان `lastScanAgeMs` و`stale`، واللوحة تعرض بانرًا أحمر «آخر مسح منذ أكثر من N دقيقة» عند التوقف/العلق. للمراقبة السريعة: `docker compose logs --tail=50 scanner` — إن رأيت `still running — skipping` متكررًا أو `forcing release` فهذا يعني دورة معلّقة/عالقة.

### قاعدة البيانات الدائمة (Turso)

> **لماذا؟** على منصات مثل Render تُمسح الملفات عند كل نشر جديد (Ephemeral Filesystem)، فيضيع تاريخ التنبيهات وتصلك رسائل مكررة. Turso قاعدة SQLite سحابية دائمة، والمشروع يستخدم `@libsql/client` التي تعمل معها ومع الملف المحلي بنفس الكود.

**القيم توضع في مكانين:**
- **محليًا**: في ملف `.env` بجذر المشروع (يُحمَّل تلقائيًا عبر dotenv):
  ```env
  TURSO_DATABASE_URL=libsql://emarsi-db-yourname.turso.io
  TURSO_AUTH_TOKEN=eyJhbGciOi...
  ```
- **على Render**: Dashboard → الخدمة → تبويب **Environment** → **Add Variable** لكل من `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` (Render لا يقرأ ملف `.env` — يعيد النشر تلقائيًا بعد الحفظ).

**الحصول على الرابط والتوكن:**

1. أنشئ حساب في [turso.tech](https://turso.tech) (الخطة المجانية كافية) ثم ثبّت الـ CLI:
   ```bash
   npm install -g @turso/cli        # أو: brew install tursodatabase/tap/turso
   turso auth login
   ```
2. أنشئ قاعدة البيانات:
   ```bash
   turso db create emarsi-scanner
   ```
3. احصل على **الرابط** (قيمة `TURSO_DATABASE_URL`):
   ```bash
   turso db show emarsi-scanner --url
   # مثال: libsql://emarsi-db-yourname.turso.io
   ```
4. أنشئ **توكن** (قيمة `TURSO_AUTH_TOKEN`):
   ```bash
   turso db tokens create emarsi-scanner
   ```
   (يمكن تجديده لاحقًا بـ `turso db tokens revoke` ثم `create`.)
5. ضع القيمتين في `.env` محليًا وفي Environment على Render، ثم أعد التشغيل.

**سلوك افتراضي آمن:** إذا تركت المتغيرين **فارغين** يعمل المشروع كالسابق على ملف محلي `data/scanner.db` — أي أن الاختبارات والتطوير المحلي تعمل بدون حساب Turso إطلاقًا.

## 6) النشر على خادم يعمل 24 ساعة

### السيناريو المقترح: Oracle Cloud Free Tier (Always Free)

> الطبقة المجانية الدائمة تُعطي VM بـ 4 OCPUs من معمارية **Ampere ARM64** و24GB RAM. ملفاتنا جاهزة لها مباشرة (بلا خطوات cross-compilation).

1. أنشئ حساب في [Oracle Cloud](https://cloud.oracle.com) → انتقل إلى **Compute > Instances > Create instance**.
2. اختر صورة **Ubuntu 22.04/24.04** + Shape من نوع **VM.Standard.A1.Flex** (ARM), ثم أنشئ المفتاح SSH وشغّل الجهاز.
3. اتصل بالجهاز وثبّت Docker:
   ```bash
   sudo apt update && sudo apt install -y docker.io docker-compose-v2
   sudo systemctl enable --now docker
   ```
4. انسخ المشروع:
   ```bash
   git clone <هذا المستودع> && cd emarsi
   cp .env.example .env
   nano .env    # املأ التوكن وكل القيم
   ```
5. شغّله كخلفية (سيعيد تشغيل نفسه تلقائيًا بعد أي إعادة إقلاع `restart: unless-stopped`):
   ```bash
   docker compose up -d --build
   ```
6. افتح منفذ 3000 في **الشبكة**: في Oracle Cloud افتح VCN → Security List → أضف Ingress Rule للـ TCP `3000` (من المصدر `0.0.0.0/0`).
7. افتح لوحة التحكم: `http://<IP_الجهاز>:3000`

### اختياري: دومين + HTTPS (nginx reverse proxy سريع)

```bash
sudo apt install -y nginx
# أنشئ /etc/nginx/sites-available/okx-scanner:
#   server_name scanner.example.com;
#   location / { proxy_pass http://127.0.0.1:3000; proxy_set_header Host $host; }
sudo ln -s /etc/nginx/sites-available/okx-scanner /etc/nginx/sites-enabled/
sudo nginx -s reload
```

ثم أضف شهادة مجانية: `sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx -d scanner.example.com`

### بدائل تشغيل 24 ساعة أخرى

- **Raspberry Pi في المنزل:** نفس خطوات Ubuntu (resolver: `docker compose up -d --build` على صورة `node:24-slim/arm64` مباشرة). أضف IP ثابتًا وافتح المنفذ في الراوتر إن أردت الوصول الخارجي.
- **Hetzner / DigitalOcean VPS:** نفس الخطوات (معمارية x64 — تعمل بدون تعديل).

## 7) الواجهة والخريطة التقنية

### لوحة التحكم (`.html` واحد)

- أزرار تبديل **الفريم** أعلى الصفحة: `1 ساعة / 4 ساعات` (تُبنى من `TIMEFRAMES`). يُعرض في الجدول فقط نتائج الفريم المختار، والتبديل فوري دون إعادة تحميل الصفحة (البيانات محفوظة في الخلفية للفريمين). عنوان الإعدادات يعكس الفريم المختار ديناميكيًا.
- بطاقات: حالة الخدمة · آخر دورة مسح · الدورة القادمة (عدّ تنازلي) · عدد العملات المفحوصة · عدد المطابقة (للأخير، ضمن الفريم المختار) · فلتر السيولة.
- جدول يبين: الرمز · السعر · **السعر الحالي** · **سعر الإشارة** · نسبة التغير · RSI · شارة التقاطع · **الشموع منذ الاكتشاف** · **وقت الاكتشاف** · شارة الحجم.
- عمود **وقت الاكتشاف** يقرأ `detected_at` من جدول `alerts` (وقت أول مطابقة للعملة بذلك الفريم، يُسجَّل حتى لو لم يُرسَل تيليجرام) ويُعرض كساعة رقمية عربية: اليوم نفسه `2:46 ص`، الأمس `أمس 2:46 ص`، والأقدم `2:46 ص 12/8`.
- عمود **الشموع منذ الاكتشاف** يعدّ كم شمعة كاملة مرّت منذ **شمعة الإشارة نفسها** (`cross_ts` في `alerts` — timestamp شمعة أول تقاطع، يُسجَّل مرة واحدة ولا يُحدَّث عبر الدورات): `floor((الآن − cross_ts) / مدة الشمعة)`، والمدة حسب الفريم المختار (60 دقيقة للـ1H، 240 للـ4H). الرقم الأكبر = الإشارة أقدم، وينمو تلقائيًا مع بقاء العملة مطابقة. للاكتشافات القديمة قبل إضافة العمود يعوّض بـ`detected_at` (فارق أقصاه شمعة واحدة).
- عمود **السعر** يأتي من **آخر شمعة مقفلة** على الفريم المختار (`confirm = 1`) — نفس الشمعة والسلسلة اللي حُسبت عليها EMA/RSI/الحجم، **وليس تيكرًا لحظيًا منفصلًا**. تحت السعر سطر صغير **«آخر مسح»** يوضّح عمر البيانات (يتحدث اللوح فقط مع كل دورة مسح، وقد تتأخر عن الشارت الحي بمقدار فترة المسح — لذلك قد يختلف السعر المعروض عن «آخر شمعة مقفلة» على الشارت بينما شمعة جديدة قيد التكوين).
- عمود **السعر الحالي** (بجانب «السعر»، عمود مستقل غير بديل) يقرأ `scans.ticker_price` — `last` من طلب التيكرات نفسه (طلب واحد في الدورة، بلا WebSocket)، فيُحدَّث كل دورة مسح (افتراضي 5 د) ويعكس السعر الحي الفعلي للعملة. تحته نسبة الفرق % مقابل سعر الشمعة (أخضر/أحمر حسب الاتجاه)، وتظهر `—` إن لم يتوفر تيكر للرمز.
- عمود **سعر الإشارة** يعرض `alerts.cross_price` — **سعر نقطة تقاطع EMA** (نفس "المثلث الأخضر" في الشارت): يُحسب بتحليل خطي بين إغلاق الشمعتين المحيطتين بالتقاطع عند **أول** اكتشاف، ويُسجَّل مرة واحدة ولا يتغير. تحته نسبة **التغير منذ الإشارة** % مقابل السعر الحالي (`ticker_price` أو سعر الشمعة عند غيابه) — مثل `+6.8% منذ الإشارة` (أخضر/أحمر). الإشارات القديمة قبل إضافة العمود **تُعبَّأ تلقائيًا** من الشموع في أول دورة بعد التحديث (باستخدام `cross_ts`)، وتظهر `—` فقط إذا تعذّر استرجاع الشمعة التاريخية.
- عمود **نسبة التغير** فيه قائمة اختيار للفترة: `4س / 1س / 15م / 5م` (الافتراضي 4س). القيّم محسوبة مُسبقًا أثناء المسح من سلسلة `CHANGE_BAR` (افتراضي 5د) بفارق "السعر الحي الآن مقابل السعر قبل الفترة" — فتبديلها فوري دون إعادة مسح، والجدول **يُرتَّب تلقائيًا تنازليًا** حسب الفترة المختارة (الأعلى موجبًا أولًا، ثم الأقل، والعملات بلا قيمة لفترة معينة في الأسفل). إن لم تكفِ البيانات لفترة معينة تظهر `—`.
- تبديل بين «المطابقة الآن» و«كل العملات»، وتحديث تلقائي كل 60 ثانية + زر تحديث يدوي.

### بنية الجدول (Turso عند ضبط `TURSO_DATABASE_URL`، أو محليًا `data/scanner.db`)

```sql
scans(id, symbol, timeframe, timestamp, price, ticker_price, rsi, ema_cross, volume_ok, matched,
      change_pct, change_5m, change_15m, change_1h, change_4h, last_candle_ts, higher_tf_warning)
      -- last_candle_ts = timestamp شمعة التقاطع نفسها (يعتمد عليها عمود "الشموع منذ الاكتشاف")
alerts(symbol, timeframe, detected_at, last_seen_at, sent, cross_ts, cross_price)
      -- حالة منع تكرار التنبيه (لكل عملة+فريم)
      -- detected_at يُسجَّل دائمًا عند أول مطابقة حتى لو فشل الإرسال؛ sent=0 → يُعاد إرسال الرسالة بالدورة التالية
      -- cross_ts = شمعة أول تقاطع (يُسجَّل مرة واحدة ولا يُحدَّث) — يعتمد عليه عمود "الشموع منذ الاكتشاف"
      -- cross_price = سعر نقطة تقاطع EMA (تحليل خطي بين الشمعتين، مرة واحدة) — يعتمد عليه عمود "سعر الإشارة" ونسبة "منذ الإشارة"؛ يُعبَّأ تلقائيًا للقديم من الشموع
state(key, value)                                     -- أدوار ومعدّات التشغيل
```

للاطلاع على البيانات يدويًا:
```bash
# Turso (عن بعد):
turso db shell emarsi-scanner "select * from scans where matched=1 order by timestamp desc"

# محليًا (خلال Docker `data` volume):
docker compose exec scanner node -e "const{createClient}=require('@libsql/client');createClient({url:'file:/app/data/scanner.db'}).execute('select * from scans where matched=1 order by timestamp desc').then(r=>console.log(r.rows))"
```

## 8) استكشاف الأخطاء

| الأعراض | السبب والحل |
|---|---|
| `status: error` في اللوحة، و`fetch failed` في السجل | لا إنترنت/ DNS محجوب. تحقق من `OKX_BASE_URL` وأن HTTP 443 غير محجوب. لا يتوقف البرنامج — يتكرر في الدورة القادمة. |
| `Telegram API rejected` / 401 | توكن خاطئ أو منتهي. أعد توليده من BotFather. |
| 403 `Forbidden` عند الإرسال | البوت ليس عضوًا مشرفًا في المجموعة، أو لم تفعّل Start مع البوت. |
| نتائج فارغة دائمًا | راقب الرسالة الأولى عند الإقلاع: `Scan done ... matched=0` طبيعي إذا لم يكن هناك تقاطع حاليًا. تحقق من `TIMEFRAMES`/`TIMEFRAME` و`CANDLES_LIMIT`. |
| إزعاج تنبيهات | ارفع `RSI_MIN`/`RSI_MAX` أو خفّض عدد الفريمات في `TIMEFRAMES`، أو فعّل `DRY_RUN` مؤقتًا للفحص. |
| السجلات | داخل حاوية: `docker compose logs -f scanner` — الملف: `logs/app.log` (volume `logs`). |
